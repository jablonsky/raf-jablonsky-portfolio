Spanning Tree Protocol: from L2 fundamentals to OT resilience

Redundant switch links improve fault tolerance only when the network can prevent loops and recover predictably. This technical reference examines STP and RSTP, then considers their implications for operational technology.

Reviewed knowledge article · 25 October 2026 · Conceptual guide; the example commands below are illustrative, not evidence of a newly completed test.

1. Engineering problem: redundant Layer 2 paths

Ethernet switches flood broadcast frames, and unknown unicasts may also be flooded. Unlike routed IP packets, Ethernet frames do not have a general-purpose hop-limit field. A physical loop can repeatedly circulate flooded frames, cause duplicate frames and destabilise MAC address learning. The objective is to keep physical redundancy while maintaining a loop-free active forwarding topology.

2. How spanning tree decides

IEEE spanning tree protocols elect a root bridge based on the lowest Bridge ID (priority plus extended system ID where used, then MAC address). Each non-root switch selects its best root port according to path cost and tie-breakers; designated ports forward on their segments while alternate paths are prevented from forwarding user traffic.

Bridge priority and link path cost are engineering controls, not merely defaults. Intentional root placement is preferable to accidentally allowing an access switch to become root.

3. Classic STP and RSTP

Classic IEEE 802.1D STP uses blocking, listening, learning and forwarding port states; transitions may be slow. IEEE 802.1w Rapid Spanning Tree Protocol (RSTP) uses discarding, learning and forwarding states, with roles and rapid proposal/agreement mechanisms that can shorten recovery when conditions permit. Actual convergence depends on topology, link type, configuration and failure mode: 'rapid' is not a guarantee of zero disruption.

4. Practical inspection on Cisco IOS

show spanning-tree
show spanning-tree vlan 110
show spanning-tree interface ethernet0/1 detail
show interfaces trunk

Check the elected root, bridge and port IDs, active port roles, cost, and any unexpected topology changes. Syntax and available commands vary by software image. On edge interfaces, protections such as BPDU Guard can reduce the risk of an inadvertently connected switch; apply them only to correctly identified edge ports.

5. What is different in OT?

An industrial network may carry cyclic controller communications, HMI updates and supervisory traffic. A topology reconvergence that is merely inconvenient in an office may interrupt time-sensitive traffic or affect plant availability. Review expected recovery against application tolerances, failure modes, vendor guidance and maintenance constraints.

STP/RSTP is not a universal industrial high-availability solution. Depending on the equipment and required recovery behaviour, technologies such as MRP, PRP or HSR may be more appropriate; their suitability must be engineered and tested, not assumed. Segmentation and network security controls remain separate requirements from loop prevention.

6. Suggested repeatable lab experiment

  1. Create three switches in a redundant triangle in an isolated lab.
  2. Record bridge IDs, root election, port roles and VLAN-specific state.
  3. Ping between test endpoints and capture traffic while disabling one forwarding link.
  4. Measure loss and recovery with timestamps; repeat trials and distinguish control-plane events from application recovery.
  5. Document switch image, protocol mode, timers, configurations and limitations before making performance claims.

Evidence status: this experiment is proposed, not reported as completed. Add actual captures, CLI outputs and measurements only after testing.

Engineering takeaway

Physical redundancy does not automatically provide operational resilience. A resilient Layer 2 design requires deliberate root placement, port safeguards, awareness of reconvergence and verification against the operational requirement.
